Read-only audit; no files modified. Findings are source-confirmed; GUI reproduction tests below were not executed.

1. **INCR paste stalls when copy mode intercepts a chunk.**  
   **`x.c:540–541, 575–589, 620–625`**  
   Returning from `selnotify()` without deleting the property leaves the selection owner waiting for acknowledgement. Exiting copy mode does not retry the ignored event.  
   **Test:** Use a selection owner that sends delayed INCR chunks. Start pasting, enter copy mode before the next chunk, then exit. Transfer remains stuck instead of completing or cancelling cleanly.

2. **Bracketed INCR paste is split into separate pastes, including an empty final paste.**  
   **`x.c:545, 562–573, 605–609`**  
   `ofs` resets for every property notification, so each INCR chunk receives its own `ESC[200~` / `ESC[201~` pair. The zero-length termination property receives another pair.  
   **Test:** Enable bracketed paste in a raw-input recorder and paste several megabytes using `xclip`. Expect one enclosing pair; observe multiple pairs and a final empty paste. Applications can process partial pasted commands independently.

3. **Transparent background pixels are not premultiplied.**  
   **`x.c:837–839, 870–874, 1229–1230`**  
   Alpha is reduced while RGB remains unchanged. ARGB rendering/compositing requires premultiplied RGB, producing overly bright backgrounds, particularly with light OSC-selected background colors.  
   **Test:** Under a compositor, launch with `-A 0`, then issue `printf '\033]11;#ffffff\007'`. Blank background should be fully transparent; inspect the resulting pixels/composite for retained white RGB. Repeat at `-A 0.5` over black.

4. **“Physical QWERTY” copy commands actually depend on the first configured layout.**  
   **`x.c:1907–1910`**  
   `XLookupKeysym(..., 0/1)` selects first-group symbols, not physical QWERTY positions. Russian commands work with `us,ru`, but fail with `ru,us` or Russian-only configurations.  
   **Test:** Configure `setxkbmap -layout ru,us`, enter copy mode, and press physical H/J/K/L, V and Y. Navigation/select/yank fail because `browseinput()` receives Cyrillic keysyms.

5. **Modified Enter silently becomes ordinary Enter with Caps Lock or additional modifiers.**  
   **`config.h:263, 353–355`; `x.c:1845–1847`**  
   Matching is exact, `LockMask` is not ignored, and the fallback accepts every modifier. Thus CapsLock+Ctrl+Enter sends CR rather than `ESC[13;5u`; CapsLock+Alt+Enter loses its ESC prefix. Ctrl+Shift+Enter and Ctrl+Alt+Enter also collapse to CR.  
   **Test:** Record raw input for Ctrl+Enter and Alt+Enter with Caps Lock off/on, then test modifier combinations. This can submit input unexpectedly.

6. **Copy-mode search cannot match text containing adjacent wide characters.**  
   **`browse.c:113–125`**  
   Search compares consecutive terminal cells with consecutive query runes, without skipping `ATTR_WDUMMY` cells. A wide character introduces a dummy cell between visible characters.  
   **Test:** Print `中文`, enter copy mode, search `/中文` and press Enter. The visible string is not found; ASCII searches work.

7. **Focus events still write to the child during read-only copy mode.**  
   **`x.c:1820–1840`**  
   Keyboard, mouse and paste paths check `browseactive()`, but focus reporting does not. This violates strict “no user-event input to the child” isolation.  
   **Test:** In a raw-input recorder, enable focus reporting with `ESC[?1004h`, enter copy mode, and focus another window and back. The child receives `ESC[O` and `ESC[I` while copy mode remains active.
